# No weight-four checks for [[11,3,3]]: certified optimal check weights

Authors: Yifan Jing and Yue Tu (University of Michigan). License: Apache-2.0.

This repository answers QIQCOP problem [op_458e9e86](https://qiqc-op.com/problem/op_458e9e86ccbddccb/)
(*Weight-four generators for an [[11,3,3]] stabilizer code*). It also determines every
distance-three entry with 10 ≤ n ≤ 12 left open in Table II of
Wei, Han, He, Li and Liu, *Theory of low-weight quantum codes*,
[arXiv:2601.19848v2](https://arxiv.org/abs/2601.19848).

## Results

| Statement | Evidence |
|---|---|
| No [[11,3,d≥3]] stabilizer code has generators of weight ≤ 4, so **W_opt(11,3,3) = 5** | SAT + DRAT certificates (33 instances); full Lean 4 proof `LowWeight.no_weight_four_11_3_3` |
| An [[12,3,3]] code with weight-4 generators exists, so **W_opt(12,3,3) = 4** and the least length of an [[n,3,3]] code with weight-4 checks is **12** | explicit code; Lean `exists_code_12` (kernel `decide`) |
| **W_opt(11,5,3) = 7**: no weight-6 code (DRAT, 37 instances); a weight-7 code | DRAT certificates; Lean `exists_code_11_5` |
| **W_opt(10,4,3) = 6, W_opt(11,4,3) = 5, W_opt(12,4,3) = 5, W_opt(12,5,3) = 6, W_opt(12,6,3) = 8** | explicit codes meeting the lower bounds of Wei et al.; Lean `exists_code_*` |

All constructions are pure codes. Their distance is exactly 3: every weight ≤ 2 Pauli operator
anticommutes with some generator, and a weight-3 logical operator exists. The generators are in
`constructions/`, one generator per line and one character per qubit.

## How the nonexistence proof works

1. **Syndromes.** Single-qubit errors have syndromes in F₂^(n−k). The distance-3 condition
   becomes: all syndromes are nonzero, and any coincidence between two qubits is explained by a
   weight-two stabilizer element.
2. **Reductions.**
   - A code with a weight-one stabilizer element reduces to length n−1, which gives an induction on n.
   - A basis of the span W of the weight-two elements is moved to the first generators. For
     dim W ≤ 2 it is placed on fixed qubits.
   - Local Clifford operations and qubit permutations bring the code to a normal form.
3. **SAT.** The remaining cases (pure; degenerate split by dim W and layout) are encoded as
   Boolean formulas and refuted.

## Verification layers

- **DRAT certificates** (`certificates/`): CNFs generated by `encoders/` and solved by CaDiCaL
  3.0.1, which writes DRAT proofs. Every proof was checked with drat-trim (commit `2e3b2dc`), and
  each instance has a `*.solve.log` and a `*.check.log`. The CNFs are compressed with xz. The
  proofs are not stored because they are large; to regenerate and check one, run
  `unxz -k X.cnf.xz && cadical X.cnf X.drat && drat-trim X.cnf X.drat`.
- **Lean 4** (`lean/`), Lean `v4.35.0-rc2` with Mathlib at `0653561`:
  - `IsCode n m w g` is exactly the problem's Eq. (458e-conditions).
  - Every reduction is proved in Lean.
  - Each of the 61 SAT cases is a Lean theorem proved with `bv_decide`: verified bit-blasting,
    CaDiCaL, and a verified LRAT checker.
  - `#print axioms LowWeight.no_weight_four_11_3_3` lists `propext`, `Classical.choice`,
    `Quot.sound` and 49 `…_native.bv_decide.ax_*` axioms. The native axioms mean the Lean compiler
    is trusted to run the certificate checker.
  - The constructions (`Positive.lean`, `Positive2.lean`) depend only on the three standard axioms.
  - There is no `sorry`.
  - The SAT files are generated by `lean/gen/gen_sat.py`, which reproduces them byte for byte.
  - A full build takes a few CPU-hours. The hardest cases need about 20 GB of RAM, so build
    them one at a time on smaller machines.
- **Cross-validation** (`cross_validation/`): the encoders reproduce 13 distance-three values of
  W_opt(n,k,3) from Wei et al. These runs validate the encoders; they are not part of the proof.

A known quirk: the non-strict sorting constraint in `encoders/degen.py` and
`encoders/degenr.py` encodes nothing. Dropping a constraint only weakens a formula, so the
unsatisfiability results are unaffected. The Lean specification enforces the ordering.

## Layout

```
REPORT.md          first report (24 September 2026)
encoders/          Python CNF generators (pure.py, degen.py, degenr.py, degens.py) and verify_code.py
certificates/      11_3_3/ (33 instances) and 11_5_3/ (37 instances): CNF.xz + solver/checker logs
constructions/     generator strings of the seven new codes
cross_validation/  logs of the W_opt recomputation
open_entries/      search logs for the open table entries
lean/              Lean 4 project (lake build)
paper/             manuscript source (main.tex) and PDF
```

## Build the Lean proof

```bash
cd lean
lake exe cache get      # Mathlib cache
lake build              # builds LowWeight.Main, Positive, Positive2
```
